**Problem Statement
**
Patients often struggle to understand the technical jargon and complex terms and conditions associated with insurance policies. This confusion can lead to unexpected bills, where patients believe their costs are covered, only to find out later that they owe money. When patients seek clarifications, they are referred back to the intricate terms and conditions, leaving them frustrated and feeling misled. 

RAG-based Q&A Insurance HelpMate
This helps patients understand their financial responsibility any time. The goal of this project is to design and implement a robust generative search system capable of accurately extracting relevant information and answering questions from diverse insurance policy documents.
 The bot can answer questions like ... 
1. Help me summarize the services covered in the policy
2. What is not covered as per the policy
3. If I am admitted for my surgery in a hospital, is the cost of bed covered?

Technically, we aim to achieve the following goals:
- Eﬃcient Retrieval: Develop an eﬃcient retrieval mechanism that can handle unstructured and semi-structured data formats commonly found in insurance policies (e.g., webpages, PDFs, Word documents).
- Natural Language Question-Answering (QA): Build a QA system that allows users to ask natural language questions related to insurance policies and receive accurate answers based on the indexed data.
- Granularity and Context: Generate responses with granular details, including specific clauses within policies and their meanings. Additionally, ensure that the system maintains context during conversations.

This repo provides implementation of RAG(Retrieval Augmented generation) using LlamaIndex
Python Code Breakdown
- Setting up libraries
- Basic Solution PoC using high-level API of LlamaIndex. It has basic structure of data
loading, indexing, storing, query engine and response. Enhancements#1 to Enhancement#6 to improve on the basic PoC as observations are made on the response
received.
1. Data source: PDF Documents
2. Loading: SimpleDirectoryReader is used for loading the documents.
3. Data Pre-processing: Chunking using Nodeparser (Enhancement #1) to create chunks of size 512 tokens. We enhanced (Enhancement #4) by creating embeddings of the node. This improved the accuracy of responses.
4. Index Creation : Building an index using VectorStoreIndex from the documents. We also enhanced (Enhancement #2) by using chromadb as a vector store. We used ChromaVectorIndex to create index and improved retrieval time.
5. Query Engine: Setup the query engine such that once the query is passed, the system queries the index and prints the responses. We enhanced (Enhancement#3) to retrieve more context for LLM by passing the similarity_top_k=5 argument to the as_query_engine method. This helped create accurate and well informed responses. We also created a response pipeline (Enhancement #5) to allow the user to hold a conversation with the RAG system.

- Testing Pipeline: Setup a feedback loop for user testing and collecting good/bad ranking of answers delivered to gauge the accuracy of the responses.
- Specialized Solution PoC using low-level API. We learnt from the testing pipeline. We enhanced the data ingestion and retrieval pipeline to generate granular responses that are accurate with reference to source file and page number. We used PromptT emplate and ChatEngine to ground the chatbot to the context and the uploaded documents only.
1. Used Pdf plumber to extract both regular and tabular text as text chunks
2. Created a data frame containing the text chunk and meta data like page number, document title etc
3. Generated and stored using the dataframe using OpenAI and ChromaDB
4. Setup semantic search pipeline using distance to find similarity.
5. Used prompt templates to ground chatbot to queries around HDFC insurance policy only. We also noticed that the chatbot could suggest a policy name that was not part of the document folder.
6. Used ChatEngine to handle the conversation instead of directly accessing the Q & A function of the query engine. This gives more control on the responses generated by the RAG system.
